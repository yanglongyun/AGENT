# 0.0.9 — 权限模式

`rule/` 是一次完整的探索:把 `ai` / `agent` / `web` 各拷一份,在副本上做权限,
原包一个字节不动。这一版记录它的设计和踩到的坑;结论在 0.1.0 里并回主线。

## 一、要解决什么

在这之前 Agent 没有任何审批机制 —— `bash` 工具拿到命令就执行。
但「每一步都问」和「什么都不问」之间缺的那一档,才是日常真正需要的:
**不问,但仍然受约束**。

约束从哪来?市面上的答案是让用户写 `Bash(rm:*)` 这样的规则。
这条路对我们不成立。所以这一版的赌注是:

> 用户用一句大白话立规则,系统把它同时变成两样东西 ——
> 写进提示词管住模型的判断,能编译的再生成一道闸管住不经过判断的路径。

## 二、三档

| 用户看到 | 内部值 | 行为 |
|---|---|---|
| 逐步确认 | `ask` | 每次工具调用都停下来问 |
| 按照规则 | `rules` | 命中任意一条规则就问;都没命中就放行 |
| 完全跳过 | `skip` | 不问不拦 |

档位是**每次发消息前的现场决定**,和工作目录并列摆在输入框上,不埋进设置页。
对话级覆盖全局默认。

## 三、规则模型:两次简化

初版有 `kind`(约束/免问/背景)和 `effect`(拒绝/询问/放行),还有对话级作用域。
用下来太抽象,砍成一句话:

> **一条规则 = 一个触发条件。命中就停下来问你。**

没有类别,没有拒绝/放行的分档,没有作用域。该不该做,用户在弹窗那一刻自己判断。

这一刀砍掉之后有两个连带结果:

- **顺序不再影响判定。** 所有规则的结果都一样(问),谁在前谁在后没有区别。
  排序退化成纯粹的排列。初版里「第一条命中的说了算」这条语义随之作废。
- **助理提议规则天然安全。** 规则只可能导致更多询问,不可能减少 ——
  初版有 `allow` 时需要额外的单向棘轮来防助理给自己发通行证,现在不需要了。

## 四、两个出口,硬度不同

```text
prompt   写进提示词 —— 永远有,靠模型自觉
match    编译成触发条件 —— 编译得出才有,由闸保证
```

`text` 是用户原话,是真相;`prompt` 和 `match` 都是它的派生物。
**改了原话必须重新编译** —— 让两者各说各话,就是把「拦得住」变成一句谎话。

编译不出来时**照实说**:界面标「没有拦截条件,这条只写进提示词」,
不许画成拦得住。宁可告诉用户这条拦不住,也不能让他以为拦得住。

### 词汇表是闭集

```text
动作  delete overwrite move network install sudo gitPush daemon format
工具  bash read write edit
路径  glob
```

收成闭集是为了「这句话能不能落地成闸」**保存那一刻就知道**,
不用等出事才发现规则写了个空。表外的意图只能进提示词。

### 编译:硬校验 + 软复核

调模型产出结构,但一次生成不当数:

1. **硬校验** —— 闭集外的动作/工具直接丢
2. **软复核** —— 再问模型一次「这条设定忠实于用户那句话吗」
3. **降级不是失败** —— 编译不出来只留提示词出口

## 五、审批门的位置

装在 `agent/`,**不在 `ai/`**。`ai/` 依然不感知工具、不感知权限,
它只知道「执行器返回了一个结果」—— 被拒绝也是一种结果。

拒绝以**工具输出**的形式回给模型,而不是抛错中断整轮。模型于是能换招
或如实告诉用户做不了,比让它撞死在半路上有用。

**没人可问就当场拒绝,绝不挂起。** 悬着的 Promise 会把整轮永远挂住,
而挂住的那一轮既不入库也不报错,是最难查的一类故障。

## 六、请示工具

规则是**用户**定的条件,系统照着拦;请示是**助理**自己的判断 ——
规则没说到的地方它也能主动停下来问一句。默认关,在「按照规则」和「完全跳过」两档下可开。

三条边界:

- **只能增加摩擦,不能减少。** 没有任何路径能靠调用它跳过规则。
- **是判断,不是保证。** 界面照实写「别指望它每次都想得起来」。
- **它自己不过闸。** 装在 `gate()` 之后,否则就成了「为了问你而先问你」。

卡片上可以勾「同时记成规则」:**一次请示靠助理记得问,升级成规则之后由闸保证。**
写不写、写成什么是用户按的按钮,不是助理的权限。

## 七、边界:这道闸看不见什么

闸挂在**工具调用**上。模型自己写一个脚本、脚本内部去删文件,它看不见 ——
除非上真沙箱,而这一版没有。文档和界面都不许暗示相反的事。

## 八、踩到的坑

| # | 问题 | 后果 |
|---|---|---|
| 1 | `~/Downloads/**` 不匹配 `~/Downloads` 自身 | 删单个文件拦得住,`rm -rf` 整个目录反而漏过 |
| 2 | 软复核拿到的是 `动作=install;工具=bash` 这种密文 | 模型看不懂就一律答 no,正确编译被成批打回,全部降级 |
| 3 | `setMode` 依赖「PATCH → 广播 → 重拉」三跳 | SSE 一抖动点击就像没生效 —— 权限控件最不能让人怀疑 |
| 4 | `.veil` 是 `display:grid` 但隐式行是 `auto` | `.sheet` 的 `max-height:100%` 拿不到参照,弹窗冲出视口 |

第 1 条是安全 bug:最该拦的那一下反而漏过。
第 2 条更隐蔽 —— 功能表面上在跑,实际每条规则都悄悄退化成「只靠自觉」。

## 九、留给 0.1.0 的

- 匹配引擎**零测试覆盖**。这是安全相关的代码,合并回主线前必须补上。
- 注入给模型的文本里带着「(没有拦截条件兜底,全靠你自觉遵守)」——
  这句是写给用户看的,不该写给模型看,等于明着告诉它「这条没人管你」。
- `rule/ai` 是 767 行零差异的死拷贝,探索结束就该删。
