# 0.1.4 — 护盾改成规则

0.1.3 把六个文件并成一个之后,拦截链第一次完整地摆在眼前:词表、命令解析、三维匹配、
审批门。反应是:"我想象的是设一条规则,传进来,直接正则匹配,怎么会这么复杂?"
这一版从这个问题出发,把权限系统整个重做。

## 一、拦截的三种做法,和为什么都不要

**词表方案**(0.0.9 引入,0.1.2 之前一直在用):用户写大白话,模型编译成
`{ actions, tools, paths }`,动作只能从九个固定值里选,运行时正则解析命令再比对。
词表存在的唯一理由是让**模型的翻译结果可校验**:模型直接输出正则,你不知道它写得对不对;
只能从九个词里选,"delete"永远对应同一组正则。它是编译器的输出格式,不是拦截本身需要的。

**正则方案**:规则就是一条正则,对命令原文匹配。三十行,不需要词表、describe、glob 展开。
拦截能力和词表**完全一样**,都只看命令字面,`python -c "shutil.rmtree(...)"` 一样瞎。

**判决方案**:保存时什么都不生成,运行时每次工具调用问一次模型"这些规则里哪条要求先问"。
覆盖面是语义级的,判决者和 agent 独立,错误不相关。代价是每次有副作用的调用多一次模型调用,
以及不确定性。

三种都有漏洞,漏洞的性质不同:正则和词表漏的是"看不懂语义",判决漏的是"偶尔误判",
只靠模型自觉漏的是"agent 理解错任务的时候,恰恰也是它最不会想到要问的时候"。

## 二、赌

> 传统的方式有漏洞,表达式有漏洞,让模型审一次也会有漏洞,误判总是会发生的。
> 不如就赌了:赌模型可以很好地遵循用户的规则,赌它在必要的情况下确认。

赌的依据:

- 前沿模型对系统提示词里明确的"做 X 之前先调 confirm"遵循得相当好,
  尤其是给了它一个具体工具而不是"在回复里问一句"。
- 规则本来就在 instructions 里每轮重装,压缩吃不掉,前提已经满足。
- 拦截层能挡的那一小圈,恰恰是模型最不容易搞错的那一圈:`rm -rf` 该不该问,不需要正则提醒。
- **绝大多数 agent 使用者全部开了 bypass。** 弹窗的成本均匀摊在每次调用上,它挡住的风险是稀疏的;
  一轮三十次调用命中三次,两次半是误报,几天就会得出"全开"的结论。任何基于字面特征的
  拦截都卡在这个精度上,再打磨也翻不了盘。规则型的问询决定权在干活的那个模型手里,
  它知道这次 `rm` 删的是自己刚建的临时目录,不用问 —— 频率低一个量级,命中率高一个量级。

赌输的样子:长任务里模型进入"流"的状态,某一步删了不该删的东西,没问。
补救靠文件系统那一层(git、Time Machine、trash 代替 rm),不靠这个项目。

赌完的形态:

- 规则表只剩 `text` `enabled` `position`。没有 prompt、match、gate、origin,没有编译器。
- 一个总开关。启用:规则进提示词,confirm 工具在;停用:规则不进,confirm 不在,
  提示词里明说"没有任何拦截,不要问要不要继续"。
- 三档(逐步确认 / 按照规则 / 完全跳过)和对话级覆盖全部删掉。
- 出厂五条规则,首次启动铺一次,`rulesSeeded` 记一下,删了不复活。
- app 触发的轮次没人守着答卡,没有 confirm;规则照样进提示词,不随开关关掉。

agent 层里权限相关的代码只剩一个三元表达式:给了 ask 才把 confirm 发给模型。
拆完之后的目录形状见 0.1.3 第四节。

## 三、护盾改名规则

去掉硬闸之后,一条"规则"的全部机制是:一句话,每轮进 instructions。
它和系统提示词的区别只有分条、可单独开关、能从 confirm 卡上一键追加。
"护盾"承诺的是拦截,拦截没了,名字比东西大。

改名之后它的定位反而清楚了:**轻便的常驻指令通道**。"删东西之前先问我"是规则,
"回答用中文"也是规则,机制一样。行为偏好和事实性记忆都可以放进去,只是后者列表会越来越长;
等真的分不清了再谈分类,那时是真需求长出来的,现在不做。

真正还在"护"的只有 confirm 工具。规则单是"告诉它什么",confirm 是"它问你",两件事。

## 四、要盯着的一处

规则的效果取决于 confirm 的提示词写得够不够准。太宽,模型变成每步都问的弹窗机器,
回到灾难;太窄,规则形同虚设。现在是三段式:规则说了的必须问,自己拿不准的也问,
普通可逆步骤不要问。这是要靠真实使用校准的东西。问得多了,先改那段提示词,不要加机制。

## 五、顺手发现的

- UI 的规则上移下移一直在 POST `/api/rules/reorder`,后端从来没有这个端点。这次补上。
- `ui/src/permission/` 改名 `ui/src/rules/`,`usePermission` 等标识符跟着改。
- 0.1.2 欠账第 4 条"采纳护盾两态"到此关闭,以本版的规则模型替代。其余三条不变。

## 六、还没补的缺口

- 规则是全局的。桌面目录下同时放着多个项目,有的上线了必须考虑兼容,有的在开发考虑兼容就是污染代码,
  一张单子管不了。
- 规则只能人写。大量对话其实是在对齐:纠正、补充、驳斥。这些话随着对话结束就丢了。

两条都在 0.1.5 做。
