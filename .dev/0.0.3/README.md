# AGENT 0.0.3

## 版本目标

重做 0.0.2 的 Web 部分。0.0.2 的实现是能跑的原型:SSE 绑在单次 POST 上,切对话或刷新就丢流,整轮跑完才落库,中途停止或崩溃整轮丢失;界面是一个 165 行的 App.tsx,没有设计体系。0.0.3 把 Web 端重做成有工程结构的本地产品,对话体验对齐桌面级 Agent 客户端的水准。

## 核心变化

### 运行不再绑在 HTTP 请求上

`POST /messages` 落库用户消息后立即返回 202,轮子在服务端后台转;全部事件从常驻的
`GET /api/events`(SSE)广播,按 `conversationId` 认领。由此获得:

- 切对话、刷新页面、开第二个窗口都不丢流;
- 运行中的对话在侧栏亮呼吸点,busy 跟着对话走(`GET /api/runs` 十秒对账兜底);
- 断线重连是 EventSource 原生能力,重连后界面自动对账刷新。

### 逐条落库与停止收尾

每个 item(思考、正文、工具调用、工具结果)完成即落库,不再等整轮结束。停止或出错时:

1. 给没等到结果的 function_call 补一条错误输出(Responses 要求调用与输出成对,缺了下一轮请求整个被拒);
2. 落一条 `[stopped]` / `[error]` 系统留痕 —— 给用户看(界面渲染成药丸),也给模型看(进上下文);
3. 已完成的轮次全部保留,只丢正在流式的半句。

已实测:停止后继续对话,模型正常应答,上下文协议合法。

### 对话体验

- **按轮收纳**:完成的轮把过程(思考/工具/中间文本)收进「已工作 X 秒」折叠条,最终正文全宽 markdown 站在外面;进行中的轮平铺直播。
- **过程行**:图标位悬停换 chevron,展开是参数/输出双块(summary 从参数里剥掉);相邻已完成工具收成一行摘要(「读取了 3 个文件,执行了 2 条命令」);运行中的标签走扫光。
- **消息流**:粘底滚动(贴底跟走、上滚不打扰)、上滑翻更早分页 + 自动填屏、日期分隔条、复制行悬停出现(最后一条常显)。
- **输入区**:草稿按对话落 localStorage 重启不丢、拼音确认的 Enter 不误发、工作目录芯片(点开改,服务端校验存在性)、模型名标签、停止按钮。
- **空白草稿**:新对话不落库,发首条消息才建对话 —— 侧栏不攒空对话;起手式卡片点了填进输入框不直接发。
- **侧栏**:置顶/最近分组、悬停操作(置顶/重命名/删除,带确认)、运行中呼吸点、可收起,窄屏成抽屉。
- **标题**:发首条消息即取机械标题,首轮跑完后台请模型起 16 字内标题,失败保留机械的。
- **主题**:明/暗/跟随系统三档,全部颜色走设计令牌。

### 数据

- `conversations` 新增 `pinned` 列,`ensureColumn` 轻量迁移,0.0.2 的库直接用;
- 消息按 `seq` 游标分页(`?before=&limit=`);
- 内核层新增 `shouldCompact()` 导出(压缩水位判断只写一份,Web 端用它预判并广播「正在压缩」)。

## 本版取舍

- 事件通道用 SSE 不用 WebSocket:本地单机场景下行足够,EventSource 自带重连,服务端保持零依赖。
- 不做附件:内核尚无多模态输入,界面不摆做不到的口。
- 置顶组不做拖拽排序:置顶内按更新时间排,够用。
- 中途停止时,正在流式的半句不落库(item 未完成),已完成轮次全保留。

## 已知限制

- 工具执行没有人工审批,bash 无沙箱(与 0.0.2 相同,内核层课题)。
- 同一对话多窗口同看时,后开的窗口补不上当轮已流过的增量(终局对账补齐)。
- 尚无自动化测试,验证靠真实端到端手测。
